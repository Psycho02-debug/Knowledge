# Как работать с кодом

> **Когда читать:** перед проверкой правки в браузере, при выборе способа правки, добавлении режима, поля, экрана, клавиши или окна, при чистке кода.  
> **Сверено с кодом:** 2026-11-04, версия кэша `zapominalka-v159`. Номера строк — ориентир для v159, ищите по имени функции.  
> **Связано:** [performance.md](performance.md) — сравнение с прошлой версией и замеры · наверх: [CLAUDE.md](../CLAUDE.md), [ARCHITECTURE.md](../ARCHITECTURE.md)

## Проверка правок

Тестов нет, проверка ручная или через консоль браузера.

```bash
python3 -m http.server 8000
```

Через `file://` service worker не регистрируется. Браузер кэширует страницу, поэтому при проверке правок открывайте адрес с меняющимся параметром: `?v=2` — без него встроенный браузер Claude отдаёт прошлую версию из своего кэша, даже когда файл на диске уже другой.

Скрипты правок с русским текстом надёжнее класть в файл и запускать `python3 файл.py`, чем передавать через heredoc: в zsh heredoc с кириллицей однажды пришёл в Python не в UTF-8, и правка не применилась. В Python 3.9 внутри f-строк нельзя обратную косую черту — выносите значения в переменные. Во встроенном браузере Claude регистрация service worker не проходит даже у неизменённой версии — это особенность среды; логику кэша проверяйте напрямую через Cache API.

**Синтаксис без браузера:** вырежьте содержимое большого `<script>` (строки ≈7342–21851) в файл и запустите `node --check файл.js` — так ловятся незакрытые скобки и шаблонные строки до загрузки страницы.

**Правки большими кусками** — Python-скриптом с проверкой `assert s.count(старое) == 1` перед каждой заменой: правка либо встаёт ровно в одно место, либо скрипт падает, ничего не испортив.

**Временные файлы** проверок называйте `_baseline.html` и `_test_*.html` и удаляйте перед коммитом. В zsh `rm _baseline.html _test_*` падает целиком, если `_test_*` ничего не нашёл, — удаляйте по одному или через `rm -f`.

**Что ломалось чаще всего:**

- все девять режимов материала и три вида скрытых слов — общая функция отрисовки слов задевается почти любой правкой;
- длинный текст в сто и больше строк — прокрутка, перекрытие нижней панелью, производительность;
- горизонтальная ориентация — нижняя панель перестраивается в один ряд;
- ширина 375px — на ней первым появляется горизонтальное переполнение;
- экран «Материалы» сразу после запуска: приложение открывается прямо в папке «Термины», и всё, что мешает первым касаниям, видно именно здесь.

**Ловушка автоматизации:** во вкладке, которая не отрисовывается (`document.visibilityState === 'hidden'`), CSS-переходы не продвигаются и застревают на стартовом значении, а `requestAnimationFrame` не срабатывает. Замер покажет неверную величину, хотя код исправен. Проверяйте такое скриншотом — он форсирует отрисовку — либо временно отключайте переход. Приложение к тому же само не перерисовывается в фоне (`render()` при `document.hidden` только откладывает работу); для проверок это обходится подменой `document.hidden`.

Измерять поведение лучше в браузере, а не рассуждением. Несколько настоящих ошибок здесь были найдены замером, и столько же ложных тревог — сняты им же.

## Стиль кода

Комментарии объясняют **почему**, а не что. Особенно ценны те, что фиксируют неочевидное решение или причину, по которой сделано именно так, — они не дают откатить правку обратно в баг.

Пример из проекта:

```js
// Переходов здесь быть не должно: открытие слова обязано срабатывать
// мгновенно. Раньше строка transition тут стояла, но не работала —
// перерисовка пересоздавала каждый спан, а у нового элемента нет
// предыдущего значения, с которого можно анимировать.
```

Форма объекта материала задаётся в одном месте — `ensureTextStudyData()`. Новые поля добавляются туда, и старые сохранения продолжают открываться.

Пользовательский текст в разметку — только через `escapeHtml()`, а в атрибуты — через `escapeHtmlAttr()`: первая не экранирует кавычки ([rendering.md](rendering.md), «Экранирование»).

Комментарии в коде местами устарели (например, у `getTokenLineNumbers` упомянуты номера на чипах, которых больше нет). Сверяйтесь с кодом, а встретив устаревший комментарий в месте правки — поправьте его.

## Рецепты изменений

**Новый режим изучения материала**

Вариант экрана скрытых слов (как «Строка по кругу») — не новый `state.mode`, а значение `practiceMode`: карточка на экране выбора зовёт `openTermInMode(i, 'practice', 'значение')`, и в `isPracticeFocusModeEnabled` его надо добавить, если нужен фокус. Отдельный экран — так:

1. Значение для `state.mode`; ветка в диспетчере `renderPracticeView` (≈13926) с функцией `renderXxxView(text)`.
2. Подготовка в трёх местах: `setMode`, `openTermInMode`, `navigateToTerm` — для сброса флагов вроде `xxxFlipped`.
3. Кнопка во **всех девяти** панелях режимов ([ARCHITECTURE.md](../ARCHITECTURE.md), §4) и карточка на экране выбора (`renderChooserView`).
4. По желанию — цифра в `switchStudyModeByHotkey` и описание в README.

**Новое поле материала** — `ensureTextStudyData`. Если в нём индексы слов — ещё перенос в `remapProcessedTextState`, `repairWordIndexAlignment`, `applyPunctuationSplitToText`. Если оно должно переживать копирование — формат переноса.

**Новый экран** — ветка в `renderScreen`, функция перехода, которая ставит `state.view` и сбрасывает лишнее, и вход в `handleEscapeAction` для возврата назад.

**Новая клавиша** — в главный диспетчер с учётом порядка проверок ([input.md](input.md)) и в таблицу клавиш README. Проверьте обе раскладки и то, что клавиша не перехватывается раньше, когда курсор в поле ввода.

**Новое окно** — разметка в `<body>` рядом с остальными (`.modal`), открытие через `classList.add('show')`, закрытие в `handleEscapeAction`, если нужно особое поведение.

**Любая правка `index.html`** — список «Обязательное при каждой правке» в [CLAUDE.md](../CLAUDE.md).

## Мёртвый код и наследие

Удалять не обязательно, но опираться на это нельзя.

| Что | Почему мёртвое |
|---|---|
| `checkAuth`, `authUser`, `sharedToken`, `serverVersion` | Остатки серверной версии; сервера нет |
| `importSharedFolder`, `linkAccountWithSite`, экран `shared` | Заглушки: кнопки есть, но первая только показывает сообщение, а вторая ставит флаг в профиле |
| Ветки `keys` и `keys_edit` в `renderScreen` и `openTermInMode`, поле `semanticKeys` в старых данных | Остатки смысловых ключей: оба значения ведут на выбор режима, поле не читается |
| `text.hintTypes` | Заводится, переносится и чинится вместе с полями индексов, но ни на что не влияет — осталось от прежней логики скрытия |
| `state.practiceMode === 'combined'` | Устаревшее значение; превращается в `default` |

## Как быстро сориентироваться

```bash
# Все функции с номерами строк
grep -n -E "^        (async )?function " index.html

# Где определена и откуда вызывается функция (с вызовами из onclick в разметке)
grep -n "renderTypeView" index.html

# Все глобальные слушатели
grep -n "addEventListener(" index.html

# Текущая версия кэша
head -1 sw.js
```

graphify (`graphify query …`) здесь помогает только с документацией: `index.html` он не разбирает, поэтому код ищите `grep`.
