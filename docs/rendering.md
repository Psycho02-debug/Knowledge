# Отрисовка экрана

> **Когда читать:** правка `render`, `setAppHtml`/`patchChildNodes`, разметки экранов, чипов слов, стилей практики, анимаций, длинных списков.  
> **Сверено с кодом:** 2026-11-04, версия кэша `zapominalka-v159`. Номера строк — ориентир для v159, ищите по имени функции.  
> **Связано:** [data.md](data.md), [practice.md](practice.md), [performance.md](performance.md) · наверх: [CLAUDE.md](../CLAUDE.md), [ARCHITECTURE.md](../ARCHITECTURE.md)

## Конвейер

```
render()
 ├─ приложение свёрнуто (document.hidden) → renderQueuedWhileHidden = true; выход
 │     (отложенная отрисовка выполнится по visibilitychange)
 ├─ renderGroupsMemo = new Map()          — память групп на одну отрисовку
 └─ renderScreen()
     ├─ body.practice-layout ⇔ view=practice и mode=practice
     ├─ тот же экран? (view|mode == lastRenderSignature)
     │     да  → #app.no-entry-anim (без анимаций появления), запомнить scrollY
     ├─ canPatchDom = тот же экран, view ≠ 'texts' и не просили пересборку (renderRebuilt → rebuildNextRender)
     ├─ html = renderXxxView()            — строка
     ├─ setAppHtml(#app, html, canPatchDom)
     │     нельзя патчить → innerHTML
     │     можно → <template>.innerHTML = html → patchChildNodes(app, template.content)
     │                 разное число детей → innerHTML этого поддерева
     │                 другой тег или тип узла → replaceChild(clone)
     │                 текст или комментарий → nodeValue
     │                 чип слова (data-widx) с тем же class, data-widx и текстом → пропуск (onclick не сверяется)
     │                 строка карточки (data-card-index) и isEqualNode → пропуск
     │                 элемент без вложенных тегов, не поле ввода (PATCH_VALUE_TAGS), и isEqualNode → пропуск
     │                 иначе → syncElementAttributes (и value у полей) + рекурсия
     │     другое число узлов верхнего уровня → innerHTML (экран перестроен, а у фрагмента шаблона innerHTML нет)
     │     исключение → innerHTML (запасной путь)
     ├─ после: texts → initTermCardSwipe() (только сенсорный экран) и initDragReorder()
     ├─ syncFlashcardTimer(), syncDockSpacing()
     ├─ вернуть прокрутку, если это тот же экран
     ├─ практика: syncPracticeTextAnchor() (закрепить положение текста при входе),
     │     restorePracticeScrollAnchor() (докрутить на сдвиг слова, запомненного до отрисовки)
     └─ type → syncTypeTextClamp()        — строго после прокрутки
 finally: renderGroupsMemo = null
```

Следствия, на которые опирается код:

- Экран «Материалы» всегда пересобирается целиком; поля ввода переживают перерисовку, если поддерево не пересобиралось; CSS-переходы срабатывают при патче — подробно в «Правилах» ниже.
- Отрисовка не совсем чистая, `compactMarkup` и каскад появления — тоже в «Правилах».
- **Текст практики не скачет** (`syncPracticeTextAnchor`, `capturePracticeScrollAnchor` / `restorePracticeScrollAnchor`, переменные `practiceTextAnchor`, `nextPracticeScrollAnchor`). (1) Карточка центрирует текст (`justify-content: center`), и каждое изменение высоты текста сдвигало все строки на половину прибавки. После первой отрисовки материала отступ сверху, который дал центр, мерится и закрепляется: класс `is-anchored` и `--text-anchor-top` в `style` карточки, `justify-content: flex-start`. Ключ — папка, модуль, материал, `practiceMode` и ширина окна (`getPracticeTextAnchorKey`); при повороте экрана обработчик `resize` перерисовывает и меряет заново, смена одной высоты (панель Safari) не трогает. (2) Перед отрисовкой того же экрана практики запоминается слово, куда смотрят: под фокусом, если оно на экране; середина экрана, если `toggleAllWordsReveal` поставил `nextPracticeScrollAnchor = 'center'`; иначе первое слово под липкой шапкой (двоичный поиск по `.word`). После патча — `scrollBy` на его сдвиг, если он больше 2 px (1–2 px — это `translateY` чипа под фокусом). Это ручной scroll anchoring: в Chrome он есть сам, в Safari нет. (3) Ряд «Фокус…/Открыть слово» в доке рисуется всегда, когда есть скрытые слова, кнопки только `disabled`: исчезающий ряд менял высоту дока → `syncDockSpacing` уменьшал отступ → страница укорачивалась, и браузер подтягивал её вверх.
- **Длинные списки карточек.** Сверка узел за узлом выгодна, когда меняется немногое. Когда меняется почти каждая строка (порядок `W`, смена сторон у всех карточек), дешевле собрать экран заново: `renderRebuilt()` один раз отключает патч, сохраняя отсечку анимаций и прокрутку. Выбор карточек вовсе не перерисовывает экран — `syncFlashcardSelectionDom()` правит класс и галочку строк и две подписи панели выбора. Строки помечены `data-card-index`: по нему работает быстрый выход `isEqualNode` в `patchChildNodes` (полей ввода в строках нет — у них значение в свойстве, которое `isEqualNode` не видит), выбор и якорь прокрутки. Плюс `content-visibility: auto` у `.flashcard-row`: строки за экраном не раскладываются и не рисуются. Замеры на папке в 1000 карточек и правила — ниже, «Длинные списки: точечно или начисто».
- Цели фокуса (`getPracticeFocusTargets`) внутри одной отрисовки считаются один раз — память лежит в той же `renderGroupsMemo` под строковым ключом `focusTargets:<practiceMode>:<practiceLineIndex>`; при выключенном фокусе `renderPracticeView` их не считает вовсе.

### Анатомия чипа слова (практика)

```html
<span class="word hidden-word [has-letters|has-custom-hint] [hard-word]
             [practice-focus-active]"
      data-widx="12" onclick="revealWord(12)">…</span>
```

- `data-widx` — индекс токена. Его читают патч (быстрый выход), `findPracticeWordIndex` (долгое нажатие и правая кнопка мыши), прокрутка к слову.
- Открытое слово — `.word.revealed`, клик по нему вызывает `hideWordAgain(i)`.
- Размеры (v158): плашка `.word.hidden-word` — квадрат 1.7em (`line-height: 1.12`, отступы `0.29em 0.52em`, ширину пустой задаёт невидимая цифра), `.word.revealed` той же высоты (`0.29em 0.45em`). Шаг строки практики — `size-xl` и `size-lg` 2.1em (телефон в альбомной ориентации — 2.0em), `size-md` 2.2em, `size-sm` 2.4em: между рядами плашек остаётся не меньше 0.3–0.4em, плашки не раздвигают строки, и высота текста — целое число строк при любом состоянии слов. До v158 плашка была 1.96em при шаге 1.9–2em: ряды смыкались, а рамка выделения круга и кольцо фокуса заходили на соседний ряд.
- В режиме `edit` чипы другие: `.word.pending-selection`, `.marked`, `.has-hint`, клик — `toggleMark(i)`. Знаки препинания рисуются как `.word-punct` без обработчика.
- Пустая плашка держит размер за счёт `:empty::before { content: '0'; visibility: hidden }` — невидимой цифры.
- Группа (`hiddenWordGroups`) в режиме `hints` рисуется одним чипом у ведущего слова; остальные слова группы пропускаются (`suppressedIndexes`).

## Правила

### Перестроенный экран собирается начисто

`setAppHtml` патчит экран, только если число узлов верхнего уровня не изменилось; иначе собирает его через `innerHTML`. Раньше в этом случае `patchChildNodes` копировал `innerHTML` нового родителя — а им был фрагмент шаблона, у которого `innerHTML` нет, и на экран выходило слово «undefined». Проявилось, когда «Карточка» научилась уходить во весь экран: тот же экран, но другая структура. Новый экран со сменной структурой верхнего уровня этим и обслуживается — ничего делать не нужно.

### Экран «Материалы» не поддерживает точечное обновление DOM

`render()` обновляет экран точечно (сравнивает с отсоединённым `<template>` и переносит только отличия), но для `state.view === 'texts'` принудительно пересобирает всё через `innerHTML`. Причина: этот экран после отрисовки навешивает обработчики свайпа и перетаскивания на конкретные узлы, а точечное обновление сохраняет узлы живыми — обработчики навесились бы повторно.

**Отсюда правило: не добавляйте навешивание слушателей после `render()`.** Если нужен обработчик — либо инлайновый атрибут в разметке, либо один делегированный слушатель на `document`, повешенный однократно при старте. Так сделана отметка сложных слов.

### Переходы CSS оживают при точечном обновлении

Пока DOM пересобирался целиком, `transition` на элементах не срабатывал: у нового узла нет предыдущего значения, с которого можно анимировать. После перехода на точечное обновление узлы сохраняются — и все переходы ожили.

Так у слов внезапно появилась плавная анимация раскрытия, хотя строка `transition` висела в стилях давно и мертво. **Добавляя `transition`, проверьте, не начнёт ли он проигрываться на каждое действие.**

### Условные блоки разметки ломают фокус в полях ввода

`patchChildNodes` при разном числе дочерних узлов пересобирает всё поддерево через `innerHTML`. Если внутри такого поддерева есть поле ввода, оно пересоздаётся — и на телефоне это закрывает клавиатуру.

Поэтому в экранах с полями ввода **условные блоки нельзя вставлять и убирать** (`${cond ? '<div>…</div>' : ''}`). Рисуйте их всегда и прячьте классом с `display: none`. Так сделаны подсказка «Сейчас слово N» и сообщение об ошибке в режиме «Вписать».

### Обработчик клика у чипа слова выводится из его класса

Быстрый выход `patchChildNodes` пропускает чип (`data-widx`), если у него тот же `class`, `data-widx` и текст: onclick он не сверяет. Если действие по нажатию зависит от состояния, меняйте вместе с ним и класс — иначе на экране останется старый обработчик. Так попался выбор слов в «Строке по кругу» (v156): onclick менялся на `toggleCirclePick`, а нажатие всё равно открывало слово, пока чипам на время выбора не дали класс `circle-pickable`.

### Внутри отрисовки разметку текста менять нельзя

`render()` на время своей работы включает память групп скрытых слов (`renderGroupsMemo`): группы спрашивают для каждого слова текста, и без памяти в режиме вопросов они пересобирались сотни раз за кадр. Память живёт ровно одну отрисовку и сбрасывается в `finally`.

Отсюда правило: **функции `render…View` не должны менять `hiddenWords` и `hiddenWordGroups`**. Если изменить их посреди отрисовки, остаток отрисовки увидит старые группы. Сейчас так и есть — отрисовка только читает разметку; менять её можно в обработчиках действий, до вызова `render()`.

Совсем чистой отрисовка при этом не является: `renderTextsView` пишет `textsViewEntriesCache` (а при пропавшей папке меняет `view` и вызывает `render()`), а `renderPracticeView` переносит `practiceFocusWordIndex`, если слово исчезло после правки текста, и выключает фокус (`exitPracticeFocusMode`), когда все скрытые слова (в «Строке по кругу» — скрытые слова строки) открыты, а `getPracticeCircleSession` заводит новый счёт кругов «Строки по кругу», если открыт другой материал. На это опирается остальной код, так что убирать эти записи нельзя.

### Экранирование совпадает с сериализатором браузера

`escapeHtml()` — строковая замена ровно четырёх символов: `&`, `<`, `>` и неразрывного пробела (U+00A0 → `&nbsp;`). Так текстовый узел экранирует сам браузер; прежняя версия делала это через DOM и съедала половину времени сборки разметки. Кавычки не экранируются — для атрибутов есть `escapeHtmlAttr()`. Меняя `escapeHtml`, сверяйте результат со старой версией на всех символах Юникода.

Пользовательский текст в разметку — только через `escapeHtml()`, в атрибуты — через `escapeHtmlAttr()`. Где это ещё не так — [ARCHITECTURE.md](../ARCHITECTURE.md), «Известные риски».

### Списки собираются без пробелов между тегами

Разметку списка материалов и списка карточек пропускает `compactMarkup()` — она убирает пробелы между тегами. У карточки материала таких пробелов было больше, чем элементов, и каждый становился узлом DOM. Все контейнеры в этих списках — flex, где пробелы между элементами не рисуются, поэтому вид не меняется (проверено сравнением геометрии всех элементов со старой версией).

**Не применяйте `compactMarkup()` к разметке, где пробел значим**: в тексте материала пробелы между словами — это и есть пробелы, а между inline-элементами пробел даёт видимый отступ.

### Длинные анимации появления ломают нажатия на iPhone

Анимация появления с растущей задержкой на каждый элемент списка («номер × 0.05 с») при десятках элементов тянется секундами. Всё это время Safari на iOS принимает касания плохо: он следит, не открыло ли касание скрытое содержимое, и если в этот момент очередной элемент проявляется из прозрачности, может счесть касание «наведением» и не отдать его кнопке. Так кнопка сортировки в списке материалов не нажималась первые 3–5 секунд после запуска.

Поэтому **любой каскад ограничивайте несколькими первыми элементами** (`getTermCardEntryDelay`: не больше восьми шагов по 0,05 с): для видимой части эффект тот же, а вся анимация экрана должна укладываться примерно в секунду.

И анимируйте **только то, что видно при открытии**. Раньше анимацию появления получали все карточки списка — при трёхстах материалах триста одновременных анимаций на каждый вход в список, каждая на время работы занимала видеокарту слоем. Теперь её получают первые `TERM_CARD_ANIMATED_LIMIT` = 16 (`getTermCardEntryStyle`), остальные появляются сразу (`animation: none`) — их всё равно не видно.

### Текст практики не должен скакать

Три механизма держат текст на месте (подробно — выше, «Конвейер», пункт «Текст практики не скачет»): закреплённый при входе отступ текста в карточке (`is-anchored`), докрутка на сдвиг слова, куда смотрят (`capturePracticeScrollAnchor` → `restorePracticeScrollAnchor` в `renderScreen`), и док постоянной высоты. Отсюда правила:

- **Не прячьте и не показывайте элементы дока практики по состоянию** — гасите их `disabled`. Любое изменение высоты дока сдвигает страницу. Если кнопка меняет подпись, держите в ней обе подписи друг на друге и показывайте одну (сетка с обеими подписями в одной ячейке, лишняя — `visibility: hidden`; так была сделана «Фокус… / ↺ Скрыть все слова» в убранном «По строкам» — `.practice-swap-labels` в истории git до v154): подписи разной длины переносятся на разное число строк, и высота дока поедет.
- **Плашка должна быть ниже шага строки с запасом.** Плашка — 1.7em, шаг крупного текста — 2.1em (`size-xl`, `size-lg`; в альбомной ориентации на телефоне 2.0em). Увеличивая плашку или уменьшая `line-height`, держите зазор между ними не меньше 0.3em: иначе ряды плашек смыкаются, рамка выделения и кольцо фокуса заходят на соседний ряд, а строки с плашками становятся выше строк без них — и текст прыгает при открытии слов. Проверка — высота `.text-display-inner`, делённая на `line-height`, должна быть целым числом в любом состоянии слов. Обводки у слов рисуйте внутрь плашки (`outline-offset` отрицательный) или тенью до 3px.
- **Не возвращайте центрирование текста на каждой отрисовке** и не убирайте `is-anchored` из разметки карточки: центр пересчитывается от высоты текста, и каждое открытое слово дёргает все строки.
- **Новое действие, меняющее много текста сразу,** решает, что держать на месте: по умолчанию — первое слово под шапкой; слово под фокусом держится само; для «всё сразу» ставьте `nextPracticeScrollAnchor = 'center'` прямо перед `render()`.
- **Прокрутка к слову — только вниз и только если оно ушло под док** (`scrollWordIntoViewIfBelow`, плавно). Вверх приложение экран не тянет: пользователь уже жаловался, что экран уезжал вверх, когда фокус возвращался к началу текста.
- Проверять — замером, а не на глаз: на ширине 390 px брать слово-ориентир и сравнивать `getBoundingClientRect().top` до и после действия (после `document.body.offsetHeight`).

### Длинные списки: точечно или начисто

Папка флеш-карточек бывает на сотни и тысячи строк, и общий конвейер на ней дорог. Замеры на 1000 карточках с картинками, время действия вместе с раскладкой:

| Действие | Было | Стало | Как |
|---|---|---|---|
| Отметить карточку при выборе | 40 мс | 1 мс | `syncFlashcardSelectionDom()` — правит класс, галочку и подписи без `render()` |
| «Выбрать все» | 59 мс | 6 мс | То же, плюс `Set` вместо `includes` в цикле |
| `W`, смена сторон | 127–137 мс | 28 мс | `renderRebuilt()` — пересборка вместо сверки тысячи изменившихся строк; один раз отключает патч, сохраняя отсечку анимаций и прокрутку |
| Буква в поиске | 150 мс | 26 мс | `content-visibility: auto` у `.flashcard-row` |
| Обычное обновление экрана | 64 мс | 21 мс | Быстрый выход `isEqualNode` по `data-card-index` в `patchChildNodes` |

Правила, которые из этого следуют:

- Патч выгоден, когда меняется немногое. Если действие меняет почти каждую строку — `renderRebuilt()`, а не `render()`.
- Частое действие, меняющее один-два узла, правьте точечно, но так, чтобы DOM совпадал с тем, что нарисовала бы `render()` (класс собран без двойных пробелов, порядок классов как у `classList`) — иначе следующая перерисовка будет переписывать атрибуты зря. Проверка: после точечных правок `render()` не должна менять `#app.innerHTML`.
- Быстрый выход `isEqualNode` — только для поддеревьев без полей ввода: у полей значение живёт в свойстве, которого `isEqualNode` не видит.
- Быстрый выход `isEqualNode` есть и для любого элемента без вложенных тегов, кроме полей ввода (`PATCH_VALUE_TAGS`). Новый тег, у которого состояние живёт в свойстве, а не в атрибуте, добавляйте и туда, и в `syncElementAttributes` — иначе патч пропустит его изменение.
- **Значки в строках длинных списков — маской, а не встроенным SVG**: `<span class="mask-icon icon-…">` — пустой элемент, рисунок в CSS (`-webkit-mask-image` и `mask-image`, SVG в data-URI), цвет — `background-color: currentColor`, `pointer-events: none` (нажатие приходится на саму кнопку или ручку). Так нарисованы ручка, карандаш и корзина в карточке материала и карандаш с корзиной в строке карточки; маленькие единичные значки (сортировка, поиск, папки) остались встроенными — там выигрыша нет. SVG на значок — 3–7 узлов DOM; в списке на 300 материалов их было больше половины всех элементов, и маска сократила его отрисовку с 10 до 6 мс, папку на 1000 карточек — с 17.5 до 11 мс. Рисунок для маски берите из того же SVG дословно, включая `stroke-linecap`: у значков строки карточки концы линий не скруглены, у карточки материала — скруглены.
- `content-visibility: auto` ставит строкам запасную высоту, пока их не показали. После пересборки она временно заменяет настоящую, и восстановление прокрутки числом сдвигает список — держите якорь по строке (`getFlashcardListAnchor` / `restoreFlashcardListAnchor`). Запасная высота подобрана под обычную строку (184 px) и строку с картинкой на телефоне (352 px).
