# Запоминалка слов — правила проекта

Офлайн-приложение (PWA) для запоминания информации. Русскоязычное, для себя, работает на iPhone с домашнего экрана. Опубликовано на GitHub Pages: https://psycho02-debug.github.io/Knowledge/

## Где что описано

| Документ | Когда читать |
|---|---|
| **CLAUDE.md** (этот файл) | Всегда. Правила, инварианты и грабли, на которые уже наступали |
| [ARCHITECTURE.md](ARCHITECTURE.md) | Перед любой нетривиальной правкой. Карта `index.html` по областям, схема `state` и данных, конвейер отрисовки, порядок проверок в диспетчере клавиатуры, зависимости, рецепты («новый режим», «новое поле»), мёртвый код, известные риски |
| [README.md](README.md) | Чтобы понять, как функция ведёт себя для пользователя, и обновить описание после правки |
| [КАК РАЗМЕСТИТЬ НА GITHUB.md](КАК%20РАЗМЕСТИТЬ%20НА%20GITHUB.md) | Публикация и обновление на телефоне |

Порядок работы над задачей: этот файл → нужный раздел ARCHITECTURE.md → сама функция в `index.html` → правка → проверка в браузере → README и, если менялось устройство, ARCHITECTURE.md → версия кэша → коммит и пуш.

## Что это за код

Всё приложение — один файл `index.html` на ~17 тысяч строк и 818 КБ. В нём подряд стили (≈1–6000), статичная разметка модальных окон (≈6000–6380) и скрипт (≈6380–17300). Чистый JavaScript: ни фреймворка, ни сборки, ни единой зависимости, ни одного обращения наружу. Всё нужное лежит рядом и попадает в кэш service worker.

Рядом с ним `fonts.css` и папка `fonts/` с 41 начертанием Inter и Space Grotesk. Раньше они лежали внутри `index.html` строками base64 — 1.6 МБ из 2.3 МБ всего файла, и телефон разбирал их целиком при каждом запуске, ещё до того как приложение могло откликнуться на нажатие. Теперь браузер подтягивает только те начертания, чьи символы реально есть на экране (обычно три файла, 84 КБ).

**Начертания трогать не надо.** Имя файла и есть его содержимое, поэтому service worker при обновлении переносит их из старого кэша, а не качает заново. Если когда-нибудь понадобится другое начертание, кладите его новым файлом с новым именем, не перезаписывая существующее.

**Все функции глобальные, и на этом держится разметка.** Скрипт классический, не модуль: каждая `function` верхнего уровня попадает в `window`, а обработчики пишутся строкой — `onclick="openText(3)"`. Отсюда два следствия:

- переименовывая функцию, ищите её имя и внутри шаблонных строк — там вызовов больше, чем в коде;
- оборачивать код в модуль или IIFE нельзя: все `onclick` разом перестанут работать.

`state` объявлен через `let`, поэтому в `window` его нет. Из консоли он доступен, а из соседнего `iframe` — только как `frame.contentWindow.eval('state')`.

Ориентироваться помогает поиск по именам функций: `grep -n -E "^        (async )?function " index.html` выдаёт все функции с номерами строк.

**Язык всего:** интерфейс, комментарии, коммиты, документация — русский. Английский только в именах функций и переменных.

## Обязательное при каждой правке

**Поднять версию кэша.** Меняете `index.html` — увеличьте номер в первой строке `sw.js`:

```js
const CACHE = 'zapominalka-vN';
```

Service worker работает «сначала кэш». Без смены версии на телефоне останется старая копия, сколько бы раз пользователь ни обновлял страницу. Это причина номер один жалоб «правка не появилась».

Вторая причина уже закрыта: при установке новой версии `sw.js` запрашивает файлы приложения с `cache: 'no-cache'`. Без этого браузер брал `index.html` из своего HTTP-кэша (GitHub Pages разрешает держать файл 10 минут), и при двух версиях подряд в новый кэш попадала прошлая. Убирать это нельзя. Правка одних `.md` версию не меняет: документация в кэш не входит.

**Обновить документацию.** Новая функция или изменившееся поведение — README: раздел возможностей и, если появилась клавиша, таблица клавиш. Изменилась структура — новая область кода, поле `state` или данных, экран, слушатель, файл — ARCHITECTURE.md. Найдена новая ловушка — этот файл.

**Отправить на GitHub.** Пользователь дал постоянное разрешение коммитить и пушить без подтверждения: репозиторий `Psycho02-debug/Knowledge`, ветка `main`, доступ по SSH-ключу `claude-deploy-igra`. GitHub Pages подхватывает изменения за 1–2 минуты.

- Его материалы в git не попадают — они живут только в `localStorage` браузера, поэтому пуш никогда не рискует данными. Если в коммит когда-нибудь попало бы что-то кроме кода и документации (данные пользователя, ключи) — остановиться и спросить.
- Без `--force`.
- Сообщение коммита — по-русски, о том, что изменилось для пользователя; в конце строка соавторства, которую задаёт среда.
- Временные файлы проверок (`_baseline.html`, замеры) перед коммитом удаляются.

## Инварианты, которые нельзя нарушать

### Индексы слов — это позиции в массиве с пробелами

```js
const words = text.content.split(/(\s+)/);
```

Скобки сохраняют разделители, поэтому массив содержит слова и пробелы вперемешку. Всё, что хранится в `hiddenWords`, `revealedWords`, `halfRevealedWords`, `hardWords`, `wordHints`, `hintLetters`, `hiddenWordGroups`, — позиции в этом массиве, а не порядковые номера слов.

Любой новый код, работающий с индексами, обязан токенизировать текст **ровно так же**. Однажды разбор вставки через `match(/\S+|\s+/g)` разошёлся со `split` на один токен у текста, начинающегося с пробела: `split` добавляет в начало пустой элемент, а `match` — нет. Часть разметки встала на пробелы, и такие слова не рисовались вовсе. Теперь и разбор вставки считает индексы через `split`, а `repairWordIndexAlignment()` при запуске и при каждом сохранении материала возвращает разметку на настоящие слова.

**Новое поле с индексами слов** нужно научить переносу в трёх местах: `remapProcessedTextState` (правка текста), `repairWordIndexAlignment` (ремонт) и `applyPunctuationSplitToText` (отделение знаков препинания). Иначе после правки или при запуске оно окажется на чужих словах.

### Индекс материала бывает двух видов

`state.currentText` — позиция в массиве **папки** (`getCurrentFolder().texts`). А `openText(vi)`, свайп, перетаскивание и выбор материалов получают позицию в **видимом списке**: после поиска, фильтра «сложные», сортировки и с материалами модулей, если открыта сама папка. Перевод делает `getTextLocationFromListIndex(vi)` по `textsViewEntriesCache`, а этот кэш заполняет `renderTextsView()`.

Поэтому `toggleAttention(index)` на экране «Материалы» понимает индекс как видимый, а на остальных — как индекс в папке. Перепутать их — значит пометить чужой материал.

### Экран «Материалы» не поддерживает точечное обновление DOM

`render()` обновляет экран точечно (сравнивает с отсоединённым `<template>` и переносит только отличия), но для `state.view === 'texts'` принудительно пересобирает всё через `innerHTML`. Причина: этот экран после отрисовки навешивает обработчики свайпа и перетаскивания на конкретные узлы, а точечное обновление сохраняет узлы живыми — обработчики навесились бы повторно.

**Отсюда правило: не добавляйте навешивание слушателей после `render()`.** Если нужен обработчик — либо инлайновый атрибут в разметке, либо один делегированный слушатель на `document`, повешенный однократно при старте. Так сделана отметка сложных слов.

### Переходы CSS оживают при точечном обновлении

Пока DOM пересобирался целиком, `transition` на элементах не срабатывал: у нового узла нет предыдущего значения, с которого можно анимировать. После перехода на точечное обновление узлы сохраняются — и все переходы ожили.

Так у слов внезапно появилась плавная анимация раскрытия, хотя строка `transition` висела в стилях давно и мертво. **Добавляя `transition`, проверьте, не начнёт ли он проигрываться на каждое действие.**

### Условные блоки разметки ломают фокус в полях ввода

`patchChildNodes` при разном числе дочерних узлов пересобирает всё поддерево через `innerHTML`. Если внутри такого поддерева есть поле ввода, оно пересоздаётся — и на телефоне это закрывает клавиатуру.

Поэтому в экранах с полями ввода **условные блоки нельзя вставлять и убирать** (`${cond ? '<div>…</div>' : ''}`). Рисуйте их всегда и прячьте классом с `display: none`. Так сделаны подсказка «Сейчас слово N» и сообщение об ошибке в режиме «Вписать».

### Фокус в поле — только синхронно, внутри жеста

На iOS клавиатура поднимается, только если `focus()` вызван прямо из обработчика касания. Вызов из `setTimeout` — уже отдельная задача: поле получает фокус, а клавиатура не появляется. Поэтому `focusTypeField` ставит фокус сразу, если поле уже в документе, а кнопка «Проверить» гасит `mousedown` (`event.preventDefault()`), чтобы не забирать фокус у поля.

### Внутри отрисовки разметку текста менять нельзя

`render()` на время своей работы включает память групп скрытых слов (`renderGroupsMemo`): группы спрашивают для каждого слова текста, и без памяти в режиме вопросов они пересобирались сотни раз за кадр. Память живёт ровно одну отрисовку и сбрасывается в `finally`.

Отсюда правило: **функции `render…View` не должны менять `hiddenWords` и `hiddenWordGroups`**. Если изменить их посреди отрисовки, остаток отрисовки увидит старые группы. Сейчас так и есть — отрисовка только читает разметку; менять её можно в обработчиках действий, до вызова `render()`.

Совсем чистой отрисовка при этом не является: `renderTextsView` пишет `textsViewEntriesCache`, а `renderPracticeView` переносит `practiceFocusWordIndex`, если слово исчезло после правки текста. На это опирается остальной код, так что убирать эти записи нельзя.

### Списки собираются без пробелов между тегами

Разметку списка материалов и списка карточек пропускает `compactMarkup()` — она убирает пробелы между тегами. У карточки материала таких пробелов было больше, чем элементов, и каждый становился узлом DOM. Все контейнеры в этих списках — flex, где пробелы между элементами не рисуются, поэтому вид не меняется (проверено сравнением геометрии всех элементов со старой версией).

**Не применяйте `compactMarkup()` к разметке, где пробел значим**: в тексте материала пробелы между словами — это и есть пробелы, а между inline-элементами пробел даёт видимый отступ.

### Длинные анимации появления ломают нажатия на iPhone

Анимация появления с растущей задержкой на каждый элемент списка («номер × 0.05 с») при десятках элементов тянется секундами. Всё это время Safari на iOS принимает касания плохо: он следит, не открыло ли касание скрытое содержимое, и если в этот момент очередной элемент проявляется из прозрачности, может счесть касание «наведением» и не отдать его кнопке. Так кнопка сортировки в списке материалов не нажималась первые 3–5 секунд после запуска.

Поэтому **любой каскад ограничивайте несколькими первыми элементами** (см. `getTermCardEntryDelay`): для видимой части эффект тот же, а вся анимация экрана должна укладываться примерно в секунду.

И анимируйте **только то, что видно при открытии**. Раньше анимацию появления получали все карточки списка — при трёхстах материалах триста одновременных анимаций на каждый вход в список, каждая на время работы занимала видеокарту слоем. Теперь её получают первые 16 (`getTermCardEntryStyle`), остальные появляются сразу — их всё равно не видно.

### Открытые слова на диск не пишутся

`revealedWords` и `halfRevealedWords` — состояние экрана: любой вход в материал их обнуляет. `stringifyPersistentData()` записывает их пустыми, а в памяти оставляет как были. Раньше из-за них переход к следующему материалу после любого открытого слова переписывал на диск все данные целиком. **Не возвращайте их в запись** и не используйте эти поля как данные, которые должны пережить перезапуск.

### Экранирование совпадает с сериализатором браузера

`escapeHtml()` — строковая замена ровно четырёх символов: `&`, `<`, `>` и неразрывного пробела (U+00A0 → `&nbsp;`). Так текстовый узел экранирует сам браузер; прежняя версия делала это через DOM и съедала половину времени сборки разметки. Кавычки не экранируются — для атрибутов есть `escapeHtmlAttr()`. Меняя `escapeHtml`, сверяйте результат со старой версией на всех символах Юникода.

### Постоянных слушателей прокрутки и движения пальца нет

`touchmove` на документе подключается только на время отсчёта долгого нажатия на слово и снимается вместе с таймером. Постоянный слушатель вызывался бы при каждой прокрутке десятки раз в секунду. Новые обработчики `touchmove`, `scroll`, `pointermove` вешайте так же — только на время жеста.

### Запись на диск отложенная

`saveData()` не пишет сразу — копит изменения и сохраняет в момент простоя. Принудительно сбрасывает `flushPendingPersistence()` (вызывается при сворачивании приложения).

Поэтому сразу после действия в `localStorage` может лежать ещё старое значение. Это не ошибка, а экономия батареи. При проверке сохранения вызывайте `flushPendingPersistence()` явно.

### Селекторы в стилях повторяются

Девятнадцать селекторов верхнего уровня объявлены в `<style>` дважды — например, блок `/* Type mode styles */` скопирован целиком. При одинаковой специфичности действует последнее объявление. **Перед правкой стиля найдите все вхождения селектора**, иначе правка уйдёт в мёртвую копию.

### Панель режимов скопирована восемь раз

Кнопки «Выбор / Практика / Вписать / Игра / Тест / Строки / Вопросы / Карточка / Пример» нарисованы отдельно в каждом экране режима, и копии уже разошлись: в панелях «Пример» и «Игра» нет кнопки «Вписать», в «Пример» нет «Вопросов». Добавляя или переименовывая режим, правьте все копии (список — в ARCHITECTURE.md, §6 и §12).

## Энергопотребление — постоянное требование

Пользователь просил, чтобы приложение практически не влияло на заряд. Достигнутое состояние: **в простое не планируется ни одного таймера, ни одного кадра анимации, нет ни одной работающей CSS-анимации.**

Что нельзя добавлять без веской причины:

- `setInterval` — в проекте нет ни одного; даже таймер карточек — цепочка `setTimeout` до границы секунды;
- бесконечные анимации (`animation: ... infinite`) — постоянная работа видеокарты;
- `backdrop-filter` — пересчёт размытия на каждом кадре прокрутки;
- `filter` на элементах, которых много в списке (в тексте бывает под две сотни чипов);
- анимации свойств, влияющих на вёрстку (`width`, `height`, `padding`, `top`) — вместо них `transform`. Так, полосы прогресса растягиваются `transform: scaleX()`: анимация `width` заставляла пересчитывать раскладку примерно восемнадцать раз на каждое открытое слово. Единственное оставшееся исключение — раскрытие справки на экране обучения (`.learning-help-content`, `max-height`): аккордеон иначе не сделать, а срабатывает он по нажатию и редко.

Статичная тень с размытием допустима: она отрисовывается один раз при смене состояния. Так было сделано свечение подсветки «следующего слова», которую позже убрали вместе с кнопкой «Открыть следующее слово».

Запись стиля инвалидирует вёрстку, даже когда значение то же самое, — сравнивайте перед присваиванием. Так устроены `syncDockSpacing()` и `syncTypeTextClamp()`.

## Как проверять ускорения

Любая оптимизация здесь обязана давать **тот же результат**, что и раньше. Проверенный способ: положить рядом копию прошлой версии (`git show HEAD:index.html > _baseline.html` — именно в корень, иначе относительная ссылка на `fonts.css` не сработает и копия нарисуется системным шрифтом), загрузить обе в `iframe` с одинаковым состоянием и сравнить:

- строки разметки `renderPracticeView()` / `renderTypeView()` — побайтово, на тысячах случайных состояний;
- геометрию всех элементов экрана (`getBoundingClientRect`) — предварительно загрузив все начертания в обеих копиях;
- для функций над данными — итоговый JSON текста на случайных, в том числе испорченных, данных.

Скорость меряйте попеременно старой и новой версией по несколько раундов и берите минимум: у разовых замеров шум больше самого выигрыша. Для случайных состояний берите нормальный генератор (например, mulberry32): простой линейный давал повторяющиеся последовательности и почти не порождал действий. Временные файлы замеров перед коммитом удаляйте.

## Проверка правок

Тестов нет, проверка ручная или через консоль браузера.

```bash
python3 -m http.server 8000
```

Через `file://` service worker не регистрируется. Браузер кэширует страницу, поэтому при проверке правок открывайте адрес с меняющимся параметром: `?v=2`. Во встроенном браузере Claude регистрация service worker не проходит даже у неизменённой версии — это особенность среды; логику кэша проверяйте напрямую через Cache API.

**Что ломалось чаще всего:**

- все девять режимов материала и три вида скрытых слов — общая функция отрисовки слов задевается почти любой правкой;
- длинный текст в сто и больше строк — прокрутка, перекрытие нижней панелью, производительность;
- горизонтальная ориентация — нижняя панель перестраивается в один ряд;
- ширина 375px — на ней первым появляется горизонтальное переполнение;
- экран «Материалы» сразу после запуска: приложение открывается прямо в папке «Термины», и всё, что мешает первым касаниям, видно именно здесь.

**Ловушка автоматизации:** во вкладке, которая не отрисовывается (`document.visibilityState === 'hidden'`), CSS-переходы не продвигаются и застревают на стартовом значении, а `requestAnimationFrame` не срабатывает. Замер покажет неверную величину, хотя код исправен. Проверяйте такое скриншотом — он форсирует отрисовку — либо временно отключайте переход. Приложение к тому же само не перерисовывается в фоне (`render()` при `document.hidden` только откладывает работу); для проверок это обходится подменой `document.hidden`.

Измерять поведение лучше в браузере, а не рассуждением. Несколько настоящих ошибок здесь были найдены замером, и столько же ложных тревог — сняты им же.

## Стиль кода

Комментарии объясняют **почему**, а не что. Особенно ценны те, что фиксируют неочевидное решение или причину, по которой сделано именно так, — они не дают откатить правку обратно в баг.

Пример из проекта:

```js
// Переходов здесь быть не должно: открытие слова обязано срабатывать
// мгновенно. Раньше строка transition тут стояла, но не работала —
// перерисовка пересоздавала каждый спан, а у нового элемента нет
// предыдущего значения, с которого можно анимировать.
```

Форма объекта материала задаётся в одном месте — `ensureTextStudyData()`. Новые поля добавляются туда, и старые сохранения продолжают открываться.

Пользовательский текст в разметку — только через `escapeHtml()`, а в атрибуты — через `escapeHtmlAttr()`: первая не экранирует кавычки.

Комментарии в коде местами устарели (например, у `getTokenLineNumbers` упомянуты номера на чипах, которых больше нет). Сверяйтесь с кодом, а встретив устаревший комментарий в месте правки — поправьте его.

## Мёртвый код, о котором стоит знать

Полный список с причинами — в ARCHITECTURE.md, §13. Главное:

- `text.hintTypes` пишется в нескольких местах, но нигде не читается — осталось от прежней логики скрытия;
- смысловые ключи (`semanticKeys`, `renderSemanticKeys*`, экраны `keys` и `keys_edit`) отключены: экраны перенаправлены на выбор режима;
- `syncToServer`, `checkAuth`, `authUser` — заглушки от серверной версии; сервера нет;

Удалять не обязательно, но и полагаться на это нельзя.
